# 待机与其他状态的衔接检查

检查范围：当前工作区图集的其余 7 个动作状态，以及 16 个视线方向；hover 使用用户已批准的 v26。逐帧检查待机 → 动作一轮 → 待机，GIF 沿用原生时序。此报告没有修改其他状态，也不把动作中的合理姿态变化自动判为问题。

主体尺寸测量排除独立爱心和小碎片；基准主体范围为 `(7,83,185,195)`，宽 178、高 112。数值描述可见主体，不等同于包含半透明边缘的完整文件外接框。结果及 GIF 均以 measurements.json 所记图集哈希为准。

- **左右拖拽：切换最明显。** 依偎坐姿直接切换到侧身行走，主体宽度约为待机的 91%。向右拖拽还会从小鸡毛左/小白右切换为小白左/小鸡毛右，这是已确认的左右镜像行走设定，并非本轮误改。若继续优化，需要专门处理坐到站、起步和停步的过渡；不能简单把待机首尾塞入行走循环，否则持续拖拽会反复坐下。
- **蹭脸反应 failed：首尾体态变化明显。** 主体宽约为待机的 94%，头顶高约 8px，可见主体底边高约 2px；小鸡毛头部和两只坐姿的变化也较突出。该动作返回待机时有收窄/放宽和姿态切换感。
- **挥手 waving：较轻的头身跳变。** 落脚底边与待机一致，但动作首尾头顶高约 6px，头部、手臂及尾巴姿态不是实际待机。挥手中间的抬手属于合理动作，主要检查点在进入和返回边界。
- **等待输入 waiting：较轻的位置、手部和头部变化。** 主体宽约为待机的 94%，可见底边高约 2px；首尾手部与待机不同。程度小于拖拽、蹭脸，但并非像 v26 hover 那样端点逐像素一致。
- **检查结果 review：较轻的坐姿跳变。** 主体宽约为待机的 97%，可见底边高约 2px，放松双手的坐姿与待机单手靠近胸前的姿态有变化。
- **亲吻处理 running：与待机最接近。** 角色顺序、依偎关系、整体大小和首尾姿态基本一致，仍有约 3% 的主体宽度差和约 2px 的可见底边差。属于小幅位置/造型变化，不宜声称首尾完全无跳变。
- **16 个视线方向：落脚位置一致。** 所有方向主体底边均为 195。抬头、低头、左右转头是方向语义本身，不能用“换成待机帧”处理；大角度切换仍是离散姿态，不代表客户端具有连续插值。
- **已批准 hover v26：首尾均为真实待机首帧，中间腾空帧统一对齐落脚基准。**

建议优先处理拖拽与蹭脸；挥手、等待、审阅可另外制作与待机匹配的首尾候选，亲吻优先级较低。以上仅为检查结论，其他状态修改必须另行展示 GIF 并取得审批。
